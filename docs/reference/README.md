# Biblioteca permanente de referências — IAM Control Center

**Finalidade:** ponto de entrada operacional para documentação oficial, decisões, PRs, evidências e critérios de validação do IAM Control Center.  
**Idioma:** pt-BR.  
**Última verificação das referências e evidências do projeto:** 2026-10-24 (America/Sao_Paulo).  
**Estado:** catálogo documental; não é, por si só, prova de que um controle está implantado.

## Regras para uso desta biblioteca

1. **Documentação explica o esperado; evidência comprova o observado.** Um link oficial, um arquivo de configuração ou uma execução bem-sucedida isolada não comprova toda a segurança do sistema.
2. **Evidência deve estar vinculada ao SHA exato.** Registrar URL da execução, SHA de origem, resultado, horário UTC, ambiente e comando/etapa executados.
3. **Separar intenção de implementação.** Classificar cada item como **DOCUMENTADO**, **IMPLEMENTADO**, **VALIDADO** ou **PENDENTE**. Não promover para VALIDADO sem teste observável e reproduzível.
4. **Sem promoção implícita.** PR Draft não é autorização de merge. CI verde não autoriza migration, deploy ou modificação de production.
5. **Revalidar referências dinâmicas.** Planos, limites, APIs, versões, permissões GitHub e actions de terceiros podem mudar. Conferir a fonte oficial no momento da alteração.
6. **Nunca incluir credenciais.** Não copiar API keys, tokens OIDC, connection strings, senhas, cookies ou claims sensíveis para documentação, commits, artefatos ou logs.

## Como manter esta biblioteca atualizada

- Ao adicionar uma dependência, workflow, migration ou provedor, adicionar a fonte oficial e os critérios de aceitação neste índice e no [catálogo de fontes](permanent-source-catalog.md). Para plano/quota, a documentação oficial de planos é a referência normativa; artigos de blog são contexto complementar e não substituem a verificação da quota atual via console/API.
- Quando um PR muda de head, atualizar o SHA e voltar a executar os checks relevantes; preservar o histórico das evidências antigas como histórico, não como estado atual.
- Quando uma fonte muda, registrar a data e o que foi revalidado. Não substituir silenciosamente limites/versões citados em uma evidência antiga.
- Ao encerrar um item, registrar a evidência concreta — PR/commit, run, teste e resultado — e manter os itens não provados como pendentes.
