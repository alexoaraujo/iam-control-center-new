## Proposed protocol

Trusted isolated broker validates actual main SHA, Ed25519, actual Environment approvals, first attempt, clock, endpoint and reader binding. No direct primary consume credential in GitHub runners. Reserve unique run ID across epochs in annotated tag refs/tags/peos-g2-retired/run-<id> (no nonce or plaintext catalogue on public GitHub; only digest commitment). Existing protect-version-tags ruleset 27234225 covers refs/tags/v* only, so does not protect proposed namespace. Dedicated active tag ruleset with no bypass, exact refs/tags/peos-g2-retired/* include, no exclusions, restrict updates and deletions. Do not restrict creation with a bypass; scoped trusted service creates the ref. GitHub Contents write is repository-wide, not per-tag; use isolated broker custody and prove its privileges/other rules before live deployment. No real refs created by this fixture. POST create ref only, HTTP 201 exact ref/tag SHA; 409/422/rate limit/timeout/ambiguous response => stop, no retry or treating existing ref as success. Local Git CAS tests exercise eight independent processes; not a live GitHub API concurrency proof. Verify annotated tag object, target main and digest, no updates or deletion. Admin can change rulesets; not immutable by itself.

B2 proposed new private bucket iam-control-center-g2-retirements with Object Lock enabled, default Compliance 365 days, no lifecycle expiry. This is a proposed minimum retention duration for review, not an applied permanent lock. Prefix iam-g2/retired/v1/. Separate upload-only key restricted to writeFiles, separate reader key restricted to listBuckets/listFiles/readFiles/readBucketRetentions/readFileRetentions, exact bucket and prefix. Native B2 capability list may allow hide via writeFiles: never trust latest version; enumerate versions including hide markers, fail on any prior/extra version or incomplete listing, read exact fileId/version and byte digest, confirm Compliance and expiration through independent reader. No deleteFiles, writeFileRetentions, bypassGovernance, admin keys or G1 credential reuse. Confirm exact API capabilities and default retention by provider readback before provisioning; no post-upload retention gap accepted. Object Lock protects a version, not uniqueness of object name. No live B2 SDK or credentials in this PR.

Check complete B2 version inventory before and after GitHub reservation, then upload canonical retirement evidence (only digests/metadata) once. Verify exact version ID, bytes, Compliance and retention >=365 days; recheck tag and policy before synthetic primary handoff. Any uncertain result burns run; never retry upload or reserve after ambiguous commit, no unburn or reuse. If GitHub ref is lost, B2 history blocks reissue. If both witnesses are lost or retention expires without independently verified retirement archive, freeze and require separately approved recovery epoch; never accept missing state as fresh. Future live implementation requires trusted broker, real API negative controls, independent recovery domain, no credential reuse, atomic budget and cross-provider audit. Simultaneous compromise of both control planes remains outside proof.
